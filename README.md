### 소프트 스킬 — AI 시대에 실제로 값이 매겨지는 것들

- **문제 정의** — 모호한 요구사항을 인터뷰로 좁혀 실행 가능한 스펙으로 바꿉니다. AI는 잘못된 문제도 아주 빠르게 풀어냅니다.
- **컨텍스트 설계** — 에이전트가 옳은 판단을 하도록 규칙·경계·예시를 문서로 남깁니다. 프롬프트보다 오래 갑니다.
- **검증과 회의(懷疑)** — 그럴듯한 코드와 맞는 코드를 구분합니다. 테스트와 리뷰가 유일한 방어선입니다.
- **작게 쪼개기** — 큰 기능을 세로로 얇게 저며 배포 가능한 단위로 만듭니다. 사람에게도 에이전트에게도 같은 원칙입니다.
- **기록** — 왜 그렇게 결정했는지 남깁니다. ADR 없는 코드베이스는 3개월 뒤의 나에게 레거시입니다.

- 🧭 아이디어 → 요구사항 인터뷰 → PRD/ADR → 세로 슬라이스 이슈로 이어지는 기능 기획 워크플로우 설계
- 🧪 테스트 코드로 AI 산출물을 검증하는 습관 만들기 (Jest / Vitest)

**A frontend engineer who defines what to build and verifies what comes back — in an era where AI writes the code.**

Five years of shipping products in the React and Next.js ecosystem.
These days I spend less time typing code and more time **writing precise specs, designing context for agents, and reviewing what they produce.**
That's why my repositories hold as much workflow and automation as they do feature code.

### Hard Skills

| Area | Stack |
|---|---|
| **Core** | TypeScript, React, Next.js, React Native |
| **Build & Test** | Vite, Webpack, Yarn Berry monorepo, Jest, Vitest, Testing Library |
| **AI Workflow** | Claude Code, Codex, CodeRabbit, review automation on GitHub Actions |
| **Backend literacy** | Node.js, GraphQL, Prisma, MongoDB |

### Soft Skills — the ones that actually got repriced by AI

- **Problem framing** — turning vague asks into executable specs. AI solves the wrong problem very fast.
- **Context design** — writing down rules, boundaries, and examples so agents decide well. It outlives any prompt.
- **Verification & healthy doubt** — telling plausible code from correct code. Tests and reviews are the only line of defense.
- **Slicing small** — cutting features into thin vertical, shippable units. Same principle for humans and agents.
- **Writing it down** — recording why a decision was made. A codebase without ADRs is legacy to my future self.
